# Stock-Stock-Stock 제품 계획서 (개인용)

> 작성일: 2026-08-19 · 리서치 4건 종합 · **완전 개인용으로 확정** (수익화·배포 없음, 단 완성도 있게)
>
> **개정 2026-09-27 — 런타임 전환**: LLM은 **Codex(내 ChatGPT 구독)**, 형태는 데스크탑 앱이 아니라 **레포 안에서 도는 에이전트**로 바꾼다. 쌓이는 자산(마크다운 위키 + SQLite)과 데이터 어댑터는 그대로이고, 바뀌는 건 에이전트 런타임과 UI 껍데기뿐이다. [SPIKE-RESULTS.md](./SPIKE-RESULTS.md)의 #1~3(구독 인증·도구 호출)과 격리 관련 발견(§4, §7 실패 1건)은 Claude Agent SDK 기준이었고, **2026-09-27 Codex로 재검증 완료** (SPIKE-RESULTS §10 — 21/21, 격리는 레시피 필요).
>
> **개정 2026-09-27 (2) — 정석 점검 + 실시간 격상**: 2025~2026 투자 에이전트 연구·제품과 대조한 결과(§8) 루프 자체는 맞지만 **보유 원장 · 결정론적 계산 · 예측 채점 · 리스크 경고 · 반대 논리**가 비어 있었다. 실시간은 "공시만 필요"에서 **핵심 요구**로 격상 — LLM 없는 상시 감시 프로그램(항상 켜둔 맥) + 폰 푸시를 M3로, 증권사 연결(멀티 증권사, 토스부터)을 M4로 당긴다. 토스 Open API에 WebSocket과 수급 REST가 있다는 사실이 확인돼 §4의 증권사 판단이 바뀌었다.

## 0. 한 줄 정의

**"지식이 복리로 쌓이는 로컬-퍼스트 AI 투자 리서치 워크스페이스" — 나를 위한.**
뉴스·공시·시세를 에이전트가 수집·해석해 관계 기반 위키 지식맵으로 축적하고, 나의 투자 판단을 기록해 결과와 교훈까지 되먹임하는 **레포 에이전트**. 이 레포에서 `codex`를 켜면 도메인 도구와 규칙이 붙은 리서치 에이전트가 되고, 아침 브리핑은 예약된 `codex exec`가 만든다. 내 ChatGPT 구독으로 구동, 모든 데이터는 내 로컬에 저장.

## 1. 개인용 확정이 가져오는 단순화

| 항목 | 배포 앱이었다면 | 개인용 (확정) |
|---|---|---|
| LLM | BYO API 키 과금 (내 구독으로 남의 요청 처리 불가) | **내 ChatGPT 구독 + Codex CLI** ("Sign in with ChatGPT"). `codex exec`·Codex SDK도 플랜에 포함. 추가 LLM 비용 0원 |
| 규제 | 유료화 시 투자자문업 리스크 | **해당 없음** (대가 없음, 불특정 다수 아님) |
| 데이터 약관 | Finnhub personal 라이선스 등 회색지대 | **정확히 부합** (개인·비상업) |
| 배포·서명 | macOS $99/년 + Windows 인증서 | **해당 없음** — 앱 바이너리가 없다. `git clone` + `npm install` |
| 뉴스 저작권 | 본문 요약 재배포 리스크 | 사적 이용 범위 — 리스크 크게 낮음 (외부 공유만 안 하면 됨) |
| 멀티 프로바이더 | Anthropic+OpenAI 지원 필요 | 불필요 — Codex 단일. 단 도구가 표준 MCP라 Claude Code에서도 그대로 붙는다 |
| 사용자 계정 | 로그인·유저 ID·유저별 저장소 | **불필요** — 1인 1레포. 인증은 그 머신의 `codex login` |

> 참고 (2026-09 OpenAI 문서 확인): Codex CLI는 ChatGPT 로그인 시 Plus/Pro 구독 한도(5시간 창 + 주간 한도)에서 차감되고, 토큰은 사용 중 자동 갱신된다. OpenAI는 CI 같은 자동화에 API 키를 **권장**하지만, 자기 머신에서 자기 로그인으로 `codex exec`를 예약 실행하는 것을 금지하지는 않는다.
>
> 남에게 주고 싶어지면: 각자 clone하고 각자 `codex login`하면 끝이다 — 유저 ID가 필요 없다. 한 서버에 여러 사람이 로그인하는 **서비스형은 별개 아키텍처**이고(서버·인증·유저별 저장소), 내 구독 공유가 불가하므로 API 키 과금이 되며, 위 표의 규제·약관·저작권 항목이 전부 되살아난다.

## 2. 핵심 루프 (변경 없음)

```
[수집] 뉴스·공시·시세 → 에이전트가 이벤트/엔티티/관계 추출
[축적] 위키 지식맵: 관계 그래프 + 시간축 (과거 사건 ↔ 현재 연결)
[판단] 내 결정 → Decision 노드 (논지·확신도·무효화 조건)
[되먹임] 결과 업데이트 → 교훈 → 유사 상황 재발 시 과거 케이스 소환
```

기존 제품(AlphaSense류 SaaS, 국내 앱, 트레이딩 저널) 어디에도 이 루프 전체를 닫는 것이 없다 — 개인용이어도 만들 가치의 근거.

## 3. 기술 아키텍처

| 레이어 | 선택 | 근거 |
|---|---|---|
| 에이전트 | **Codex CLI** — 대화는 `codex`, 예약 작업은 `codex exec` | 내 ChatGPT 구독으로 구동. 에이전트 루프·파일 편집·세션·MCP 클라이언트를 공짜로 얻음. 규칙(`AGENTS.md`)과 커스텀 도구만 얹으면 됨 |
| 인터페이스 | **레포 자체** — `AGENTS.md` + 프로젝트 `.codex/config.toml` | GUI 불필요. 쌓이는 자산이 UI와 무관하므로 Electron은 껍데기일 뿐이었다. 위키 열람·그래프는 Obsidian이 대신한다 |
| 도메인 도구 | **표준 MCP 서버** (Node, stdio, `@modelcontextprotocol/sdk`) | Claude SDK 전용 `tool()` 래퍼 대신 표준 MCP → Codex·Claude Code 양쪽에서 동작. LLM 락인이 도구 계층에서 끊긴다 |
| 예약 실행 | **launchd** → `scripts/briefing.sh` → `codex exec` (아침 브리핑) | 앱을 "여는" 순간이 없으므로 트리거를 시간으로 바꾼다 |
| 실시간 감시 *(M3)* | **상시 감시 프로그램** — LLM 없는 Node 프로세스, launchd `KeepAlive`로 **항상 켜둔 맥**에서 상주. 토스 WebSocket 시세 · DART/EDGAR 빠른 폴링 · 뉴스 RSS → 규칙 매칭 → **폰 푸시 즉시**, 필요한 건만 `codex exec`로 해석해 후속 푸시 | 알림은 수 초, LLM 해석은 수십 초 뒤 따라온다. 감시 자체는 구독 한도를 쓰지 않는다. 세션이 끝나면 아무것도 안 도는 레포 에이전트의 빈자리를 채운다 |
| 알림 *(M3)* | **텔레그램 봇 (기본)** + macOS 알림 + 브리핑 최상단 | 자리를 비우면 macOS 알림은 못 본다 — 실시간이 의미 있으려면 폰 푸시가 기본이어야 한다 |
| 지식 저장 | 마크다운 정본 + SQLite 인덱스 (**Node 내장 `node:sqlite`**) | 파일이 자산으로 남고(Obsidian으로도 열림) 인덱스는 재구축 가능. 네이티브 의존성 없음 → `npm install`만으로 동작 |
| 검색 | v1: FTS5 trigram + **2글자 LIKE 폴백 라우터** → v2: + sqlite-vec 하이브리드 | 한국어는 trigram 필수(`하이닉스`↛`SK하이닉스`), 단 2글자 MATCH 불가라 라우터 필요 |
| 그래프 | SQLite nodes/edges + 재귀 CTE | 그래프 DB 도입 보류 (KuzuDB 아카이브 사태) |

### 레포 구성

```
bin/sss.mjs          ← 실행기: 격리 레시피를 적용해 codex / codex exec 를 wiki/ 에서 띄운다. deep · init · doctor · briefing · schedule (전부 대화로도 된다)
agent/AGENTS.md      ← 에이전트 규칙: 사실 규율, 제안→확인 후 쓰기, 페이지 스키마, 판단 기록, 키 취급, 비신뢰 입력, 보유·제안
agent/BRIEFING.md    ← 아침 브리핑 지시 (sss briefing 이 codex exec 에 넘긴다)
mcp/server.mjs       ← 도메인 도구 MCP 서버 (Codex 가 띄운다) · mcp/lib/ 위키·판단·EDGAR·시세·모델 라우팅(models)·예약(schedule) · mcp/test/
wiki/                ← 데이터 정본 — 코드 레포에서 제외, 자체 git 저장소 (sss init 이 만든다)
  AGENTS.md          ←   agent/AGENTS.md 를 가리키는 링크 (Codex 가 작업 디렉터리에서 읽는다)
  pages/             ←   위키 페이지 (노드 하나당 파일 하나)
  briefings/         ←   아침 브리핑 <날짜>.md + 원자료(.inbox-<날짜>.json)·상태(.state.json, git 제외)
  proposals/         ←   제안 대기열 p-YYYYMMDD-NNN.md — 브리핑이 남기고 대화에서 처리 (M2)
  portfolio.yaml     ←   워치리스트 + 보유 원장 — 도구로만 고친다 (M2)
watch/               ← 상시 감시 프로그램 (M3) — LLM 없음, launchd 상주
var/calls.jsonl      ← 도구 호출 기록 — 모델 자기보고와 무관한 감사 기록 (gitignore)
var/settings.json    ← 대화에서 바꾼 용도별 모델 (model_settings) — 위키 밖이라 승인을 거친 도구로만 바뀐다
var/briefing.log     ← 예약·대화에서 띄운 브리핑 로그 (system_status 가 끝부분을 보여준다)
.codex/config.toml   ← Phase 0 검증 스파이크 전용 (spikes/codex-runtime). 제품은 bin/sss 가 설정을 주입한다
```

- **작업 디렉터리 = `wiki/`** *(2026-09-27 M1 확정)*: 샌드박스 쓰기 범위가 위키뿐이라 **에이전트는 제품 코드(`mcp/`·`bin/`)를 고칠 수 없다** (E2E·`codex sandbox`로 확인). 위키가 별도 git 저장소라 Codex 의 프로젝트 루트도 위키가 되고, 규칙 파일은 링크로 공급한다. 원래 Phase 1 의 "작업 디렉터리를 위키 폴더로 고정"을 Codex 에서 그대로 구현한 형태.
- **설정은 파일이 아니라 실행기가 주입한다**: `wiki/`에는 레포의 `.codex/config.toml`이 닿지 않으므로 sss 서버·기능 끄기·전역 서버 끄기를 전부 `-c`/`--disable`로 넘긴다. 설정의 원본이 코드 한 곳(`bin/sss.mjs`)에 있다.
- **셸 샌드박스와 데이터 수집을 분리한다**: 외부 데이터(DART·시세·EDGAR)는 전부 MCP 도구를 거친다. 에이전트가 셸로 직접 `curl`하게 두지 않는다 — 출처 기록·공식/비공식 게이트가 도구 계층에 있기 때문이다.
- **과금 경로 고정**: `CODEX_API_KEY` 환경변수가 있으면 `codex exec`가 조용히 API 과금으로 넘어간다(보고된 사고 다수). `bin/sss.mjs`가 자식 환경에서 이 변수를 지우고, `sss doctor`가 로그인 방식과 `auth.json` 저장 모드를 점검한다.

### 지식맵 스키마 (바이템포럴)

- **노드 8종**: `Company`(티커 필수) · `Person` · `Sector` · `Theme` · `MacroIndicator` · `Event`(날짜·출처 필수) · `Decision` · `Source`(원문)
- **엣지 ~13종**: `causes` · `affects(+/-, magnitude)` · `supplies-to` · `customer-of` · `competes-with` · `belongs-to` · `precedes` · `similar-to` · `triggered-by` · `resulted-in` · `invalidated-by` · `derived-from` · **`about`**(Decision→대상 엔티티)
  - `about`이 없으면 "무엇이 이 종목에 영향을 주는가" 질의에 내 결정이 섞인다 — 스파이크에서 발견해 수정
- **모든 엣지 공통**: `valid_from` / `valid_until`(null=유효) / `recorded_at` / `confidence` / `source_ref` — "그때는 참, 지금은 아님"을 삭제 없이 표현
- **LLM 추출 규칙**: 티커 등 정규 식별자로 정합, 관계 타입 제한, 기존 그래프를 컨텍스트로 제공(중복 엔티티 방지), 모든 사실에 출처 필수

### Decision 레코드

```yaml
thesis: 판단의 논지
trigger_nodes: [촉발한 Event/Source 링크]
action: 매수/매도/관망/비중조절
confidence: 1-10
expected_outcome: 기대 시나리오 + 주관적 확률
invalidation_condition: 틀렸다고 인정할 조건   # 핵심 — 에이전트가 주기 점검
time_horizon: 유효 기간
emotion: 당시 감정
probability: 논지가 맞을 숫자 확률 (0~1)   # 확신도와 별개 — 채점용 (Phase 2)
bear_case: 반대 시나리오                   # 필수 칸 (Phase 2)
pre_mortem: "이게 틀렸다면 이유는?"          # 필수 칸 (Phase 2)
benchmark: 비교 기준 (지수 / 단순 보유)      # 채점 기준 (Phase 2)
# --- 이후 ---
actual_outcome / variance / lesson   # 결과가 아니라 프로세스를 평가
```

- **채점**: 결과가 나온 Decision은 `probability`로 Brier 점수를, `benchmark` 대비 초과수익을 계산한다 — 이 도구가 내 판단을 실제로 낫게 하는지 확인하는 유일한 방법 (§8)
- `emotion`·persona 같은 개인 맥락은 증거 해석과 분리한다 — 같은 공시도 역할 맥락에 따라 다르게 읽힌다는 결과가 있다 (§8)

### 유사 과거 상황 검색 (3층)

엔티티·태그 SQL 필터 → 임베딩 랭킹(v2) → LLM이 최종 3~5개 케이스 관련성 판단.

**시점 규율** *(2026-09-27 정석 점검)*: 과거 케이스를 평가할 때는 **그 당시 `recorded_at` 이전에 알려진 사실만** 쓴다 — 바이템포럴 스키마가 이미 이걸 가능하게 한다. LLM은 학습 시점 이전의 시장 값을 기억하고 있어 지시만으로는 미래 정보 누설을 막지 못한다 (§8).

## 4. 데이터 소스 — 계좌 없이 전부 가능

무료 실시간만 구조적으로 불가능하다(KRX 시세는 코스콤 독점 분배, 증권사 경유가 유일 경로). 공시는 DART로 무료·준실시간이 열리고, **시세·수급 실시간은 토스 계좌로 연다** *(2026-09-27 — 실시간을 핵심 요구로 격상, M4)*.

소스를 하나 고르는 대신 **용도로 계층을 나눈다**:

| 계층 | 소스 | 용도 | 조건 |
|---|---|---|---|
| **OFFICIAL** | 공공데이터포털 금융위 주식시세정보 | **위키에 영구 저장되는 시세** | 자동승인, 무료, "이용허락범위 제한 없음", T+1 13시 |
| | **KRX Open API** | 2010년~ 원본 일별 시세 | 무료, **개인 가입 가능**, 약관이 "비상업 목적만"이라 이 프로젝트와 정확히 부합. 출처 표시 의무 |

**멀티 증권사 구조** *(2026-09-27)*: 증권사 하나에 묶지 않고 **공통 어댑터 인터페이스**로 여러 곳을 동시에 등록한다.
- **등록 = `.env`에 키가 있는 것만 켜진다** (`TOSS_*` · `KIWOOM_*` · `KIS_*`). `sss doctor`가 증권사별로 토큰 발급·IP 허용 여부를 점검한다
- 공통 인터페이스: 실시간 시세 구독 · 수급 조회 · 보유 조회 · 상태 점검(토큰 만료, IP 403)
- **기능 선언**: 증권사마다 되는 게 달라서(토스는 장중 가집계 WS 없음 등) 어댑터가 자기 기능과 한도(구독 수·호출 제한)를 선언하고, 라우터는 그걸 보고 배정한다. 종목 코드·체결 형식은 공통 형식 하나로 정규화한다 — QuantConnect LEAN · NautilusTrader · CCXT 같은 멀티 브로커 프레임워크의 표준 패턴
- **고르는 건 사용자, 쓰는 건 에이전트**: 사용자는 가진 계좌만 등록하고(여러 곳이면 우선순위를 설정으로 지정), 에이전트는 요청마다 등록된 증권사의 기능 선언을 보고 알아서 고른다 — 대화에서 증권사를 지정할 필요가 없다. "키움 추가하고 싶어"라고 하면 에이전트가 발급 절차를 안내한다(키는 `.env`에 직접). 남에게 레포를 줄 때도 각자 자기 증권사만 등록하면 된다
- **구현은 하나씩**: 인터페이스는 처음부터 멀티로 열어두되, 두 번째 증권사는 필요가 생길 때 붙인다 — ① 보유가 여러 증권사에 흩어짐 ② 감시 종목이 200을 넘음 ③ 장중 수급 추정치(가집계)가 필요함
- **구독 슬롯 합산**: 토스 200(2×100) + 키움 약 100 + KIS 41. 보유 종목부터 배정하고, 한 곳이 끊기면 남은 곳으로 재구독
- **수급은 강점별로**: 장중 가집계·실시간 프로그램매매는 키움(`0w`)·KIS(`H0STPGM0`) WebSocket, 일별 확정치는 토스 REST
- **보유 원장은 증권사별로 가져와 합산** — 계좌가 여러 곳에 있으면 이게 없인 원장이 틀린다
- 비용: 인증·토큰 수명·메시지 형식이 증권사마다 달라 어댑터마다 유지보수가 든다. **실제 계좌 없이는 E2E 검증이 안 되므로** 계좌를 연 증권사부터 순서대로 붙인다 (토스 → 키움 → KIS)
- 이름 주의: 기존 `mcp/lib/quotes.mjs`의 `toss`는 **WTS 내부 API(비공식, opt-in)**이고, M4의 토스는 **공식 Open API** 어댑터라 별개다

**토스를 먼저 붙이는 이유** *(2026-09-27 — 이전 판단 "키움 1순위"를 뒤집음)*. 근거는 [토스 Open API 문서](https://openapi.tossinvest.com/openapi-docs/overview.md)에서 확인한 것들이다.
- **WebSocket이 있다** (`wss://openapi-ws.tossinvest.com/ws/v1`, 체결·호가, KRX+NXT 통합, 미국 `trade:us`). 이전 문서의 "토스는 WebSocket이 없다"는 틀렸다 — 커뮤니티가 스펙 추가를 감지한 날은 2026-08-19
- 한도: 계정당 연결 2개 × 연결당 구독 100건(채널×종목), 구독 선언 초당 5회, 180초 안에 PING. 관심·보유 종목 규모엔 충분
- **수급 REST**: 투자자별 매매동향 · 프로그램매매 · 공매도 · 신용 · 대차 (일별). 수급 범주를 계좌 하나로 연다
- 개설이 가장 쉽다
- ⚠️ **허용 IP 등록 필수** (미등록 시 403). 집 유동 IP가 바뀌면 재등록해야 한다 → 감시 프로그램이 403을 감지하면 "IP 재등록 필요"를 폰으로 알린다

키움·KIS 비교 (둘 다 같은 인터페이스로 추가 등록): 키움은 당일 개설·WebSocket·장중 수급 WS(`0w`)가 있지만 실시간 종목 수는 2026 커뮤니티 자료 전부 **100**(이전 문서의 200은 공식 확인 불가)이고 IP 등록(최대 10개) 필수. KIS는 세션당 **41건**(체결·호가·체결통보 합산), 장중 가집계·실시간 프로그램매매 WS 문서화가 가장 잘 돼 있다. **장중 투자자별 수치는 어느 경로든 가집계(추정)뿐**이고 확정치는 일별이다. LS·NH의 "3개월 체결 20건 이하 시 해지" 조항은 2026-09 재조사에서 확인되지 않았다(찾은 것은 KIS·KB의 "1년 이용 실적 없음 시 해지"와 LS 키 유효기간 1년).

**불변식 두 가지** — `spikes/kr-quotes/`에 구현·검증 완료(13/13):
1. `official === false` 데이터는 위키에 커밋하지 않는다.
2. 히스토리는 공식 키가 없으면 **조용히 폴백하지 않고** 키 발급 안내와 함께 에러를 낸다.

덕분에 비공식 엔드포인트가 깨져도 축적된 지식 자산은 무사하고 현재가만 안 보인다.

**라이선스 근거**: KRX 「시세정보 이용정책」 §2 [옵션3]은 포털의 시세 화면 표시는 허용하되 *"제3자가 전자적으로 가공·저장·재분배할 수 있는 수단(API 등) 제공"을 엄격히 금지*한다. 네이버가 공개 API를 두지 않는 것은 라이선스 의무이며, 내부 엔드포인트 스크래핑은 그 금지의 우회에 해당한다. 사람이 화면을 보는 것과 프로그램이 긁는 것은 다르다.

## 7. 확정된 결정

1. ~~수익화~~ → **없음. 완전 개인용, 완성도 우선**
2. LLM: **내 ChatGPT 구독 + Codex CLI** *(2026-09-27 변경 · 이전: Claude 구독 + Agent SDK)*
3. 스택: **레포 에이전트 (`AGENTS.md` + 표준 MCP 서버 + `codex exec`) + 마크다운/SQLite** *(2026-09-27 변경 · 이전: Electron + Agent SDK)*
4. 시장: 한국 중심 + 미국 보조 (기본 가정 — 변경 가능)
5. 사용자: **1인 1레포, 유저 ID 없음** — 여럿이 쓰면 각자 clone + 각자 로그인
6. 실시간: **핵심 요구** *(2026-09-27)* — LLM 없는 상시 감시 프로그램을 **항상 켜둔 맥**에서 돌리고, 알림은 **텔레그램 푸시가 기본**
7. 증권사: **멀티 증권사 — 토스 · 키움 · KIS를 같은 인터페이스로 등록 가능, 토스부터 구현** *(2026-09-27 · 이전: 키움 1순위 단독)* — M4
8. 형태: **판단 보조, 자동매매 없음** — 누수 없는 평가에서 LLM 에이전트 대부분이 단순 보유를 못 이긴다 (§8)
9. 조작: **모든 조작은 대화로** *(2026-09-27)* — 종목 등록·브리핑 예약과 실행·모델 설정·상태 점검을 `sss` 대화에서 말로 한다 ("아침 7시 반에 브리핑 예약해줘"). 새 기능은 MCP 도구로 내고(바꾸는 도구는 대화형 승인 + 자동 실행 거부), CLI 하위 명령은 예비 경로로 남긴다. 예외는 API 키 하나 — 대화 기록에 남으므로 `.env` 에 직접 넣는다

## 8. 정석 점검 (2026-09-27)

질문: M2·M3까지 하면 정석적이고 부족함 없는 투자 에이전트인가? → **루프는 맞고, 운영 필수 요소 다섯 개와 실시간이 비어 있었다.** 2024~2026 연구·제품을 조사해 대조했다. 링크의 날짜는 조사 시점 기준이다.

**방향이 맞다는 근거 (판단 보조 · 사람 승인)**
- 미래 정보 누설을 통제한 평가에서 LLM 에이전트는 대체로 우위가 없다: [FINSABER](https://arxiv.org/abs/2505.07078)(20년·100종목 이상에서 우위 급감) · [StockBench](https://arxiv.org/abs/2510.02209)(대부분 단순 보유 미달) · [DeepFund](https://arxiv.org/abs/2505.11065)(실거래 손실) · [PortBench](https://arxiv.org/abs/2605.27887)(90%가 균등 분산 미달)
- 업계도 사람이 승인하는 구조: [Anthropic 금융 에이전트](https://www.anthropic.com/news/finance-agents)(2026-05, "users firmly in the loop")
