## 1. 한국어 전문검색 — trigram + LIKE 폴백

`spikes/fts-ko/` · 실행: `sqlite3 :memory: < fts_ko_test.sql`

**unicode61(기본 토크나이저)은 한국어에 부적합.** `SK하이닉스`가 한 토큰이라 `하이닉스` 검색이 실패한다. 조사·복합어가 붙는 한국어에서 치명적.

**trigram이 정답이지만 2글자 쿼리가 실패한다.** 한국어 금융 용어는 2글자가 압도적으로 많다 — 금리, 실적, 환율, 공시, 매수, 매도, 유가, 배당.

| 쿼리 | unicode61 | trigram |
|---|---|---|
| `삼성전자` (원문 "삼성전자가") | ✅ | ✅ |
| `하이닉스` (원문 "SK하이닉스") | ❌ | ✅ |
| `금리` (2글자) | — | ❌ |
| `기준금` (3글자) | — | ✅ |
| `HBM3E` / `hbm` | — | ✅ (대소문자 무시) |
| 구문 `"메모리 가격"` | — | ✅ |

**해결: 쿼리 길이 라우터.** 3글자 이상 → `MATCH`, 2글자 이하 → `LIKE '%q%'`.
5,000 페이지 코퍼스 실측 결과 LIKE 폴백도 **1~2ms**로 충분하다 (trigram 인덱스가 `L1`로 LIKE를 가속). 1글자 최악 케이스도 1ms.

```
[A] MATCH '기준금'      1000건  0.000s   (인덱스 M2)
[C] LIKE '%금리%'       1000건  0.001s   (인덱스 L1)
[F] LIKE '%유%'         1000건  0.001s   (최악 케이스)
```

> 형태소 분석기(mecab-ko)는 네이티브 의존성이라 Electron 패키징을 크게 복잡하게 만든다. 개인용 규모에서 trigram+LIKE가 비용 대비 최적.

## 2. SEC EDGAR — 키 없이 즉시 사용 가능

`spikes/edgar/edgar.mjs` · 실행: `EDGAR_UA="Stock-Stock-Stock you@example.com" node edgar.mjs`

NVDA 기준 실측: 티커→CIK 매핑, 최근 8-K/10-Q 목록, XBRL 매출 시계열 확보.

**주의 — XBRL 기간 중첩**: `Revenues` 시계열에 3개월·9개월·연간이 섞여 나온다. `start`/`end` 간격으로 반드시 구분해야 하며, 안 하면 "매출이 147B에서 57B로 급감"이라는 오독이 발생한다. 도구 응답에 경고 문구를 넣어 에이전트가 오해하지 않게 했고, 실제로 에이전트가 이를 정확히 구분했다.

**연락처**: SEC는 User-Agent에 실제 연락 이메일을 요구한다. `EDGAR_UA` 환경변수로 주입하며 코드에 하드코딩하지 않는다.

## 3. Agent SDK — 구독 인증 + 커스텀 도구

`spikes/agent-sdk/agent.mjs`

`ANTHROPIC_API_KEY`가 설정되지 않은 상태에서 `~/.claude/.credentials.json`의 `claudeAiOauth` 토큰으로 인증됐다. **개인용 앱이 추가 LLM 비용 없이 구독 한도 내에서 동작함을 실증.** (`total_cost_usd`에 찍히는 값은 API 환산 상당액이며 구독 사용량에서 차감된다.)

에이전트가 스스로 두 도구를 순차 호출하고, 답변 각 줄에 근거 도구를 표기했으며, **도구가 주지 않은 정보(8-K 본문)를 스스로 "확인하지 않았다"고 구분**했다. 팩트 기반 규율이 시스템 프롬프트만으로 작동함을 확인.

**성능 기준선**: 4턴 / 2회 도구 호출 / 16초. 데일리 브리핑이 종목당 이 정도면 10종목에 3분 내외 — 백그라운드 실행으로 충분히 감당 가능.

## 4. 도구 네임스페이스 격리 ⚠️ 중요

`spikes/agent-sdk/isolation.mjs`

**문제 발견**: `allowedTools`에 우리 도구 2개만 넣었는데도 개발 환경 `~/.claude`의 플러그인 MCP 도구 **54개가 전부 노출**됐다. 에이전트가 실제로 그중 하나(`ToolSearch`)를 먼저 호출하기까지 했다. 방치하면 컨텍스트 낭비 + 사용자 환경마다 다른 동작이 발생한다.

| 설정 | 총 도구 | 외부 MCP | 빌트인 |
|---|---|---|---|
| 기본값 | 81 | 54 ⚠️ | 26 |
| `settingSources: []` | 27 | **0** ✅ | 26 |
| + `strictMcpConfig: true` | 27 | 0 | 26 |
| + `disallowedTools` | 19 | 0 | 18 |

**결론**: `settingSources: []`를 앱에서 항상 명시한다. `allowedTools`는 노출 목록이 아니라 허용 목록일 뿐이라 격리 수단이 아니다.

## 5. 위키 지식그래프 계층 — 전체 루프 실증 ⭐

`spikes/wiki/` · 실행: `node demo.mjs` · 샘플 7페이지 / 엣지 24개

제품의 핵심 주장을 실제 코드로 검증했다. 시나리오는 사용자가 원한 흐름 그대로다:
**2024-08 블랙웰 지연 → 내 비중축소 결정 → 2024-11 반증(틀림) → 교훈 → 2026-08 동일 패턴 재발 시 과거 케이스 소환.**

| 검증 | 결과 |
|---|---|
| 한국어 2글자 검색 `"실적"` | ✅ LIKE 폴백으로 자동 전환 |
| 한국어 부분어 `"하이닉스"` → `SK하이닉스` | ✅ trigram MATCH |
| 관계 기반 2-hop 탐색 | ✅ 재귀 CTE로 6개 연결 노드 |
| 바이템포럴: 무효화된 사실이 과거 시점에만 조회됨 | ✅ |
| 바이템포럴: 무효화 후에도 페이지 보존 | ✅ |
| 유사 케이스 + 결과·교훈 소환 | ✅ 태그 3개 일치 + `similar-to` 링크 |
| 끊긴 링크(오타·미작성) 탐지 | ✅ 0건 |

**바이템포럴이 실제로 작동한다.** 동일 질의 "무엇이 SK하이닉스에 영향을 주는가"에 대해:
- `2024-09-01` 시점 → 블랙웰 지연(−, 확신도 0.6)
- `2026-08-19` 시점 → 블랙웰 지연 **사라짐**, HBM 수요 견조(+, 0.9)와 루빈 루머(−, 0.3)

블랙웰 페이지는 삭제되지 않고 역사로 남아 있으며, 2026년 루빈 루머의 확신도를 0.3으로 낮게 잡은 근거로 재사용된다. **과거가 현재의 판단을 교정하는 것이 설계대로 동작함.**

### 발견된 스키마 결함과 수정

Decision → Company 관계에 `affects`를 쓰면 **"무엇이 이 종목에 영향을 주는가" 질의에 내 결정이 섞여 들어온다.** 결정은 종목에 영향을 주는 것이 아니라 종목을 *대상으로 하는* 것이다. `about` 관계를 신설해 분리했다.

→ 엣지 타입에 **`about`** 추가 (Decision/Note → 대상 엔티티).

### node:sqlite 사용 시 주의점

- **위치 파라미터와 명명 파라미터를 혼용할 수 없다.** `.all(...tags, {cur: id})` 형태가 `ERR_INVALID_ARG_TYPE`으로 실패한다. 가변 길이 IN 절이 있으면 전부 위치 바인딩으로 통일할 것.
- 재귀 CTE 탐색 시 시작 노드가 depth 2에서 되돌아온다. `WHERE id != :start` 필수.

### 전제: 무료 실시간은 구조적으로 불가능

KRX 체결·호가는 **코스콤이 독점 분배**하며, 유상 계약(외부제공사/최종이용사) 기반 B2B 상품이다. 개인이 직접 계약하는 경로는 없고 **증권사가 자기 고객에게 주는 형태로만** 흘러간다. KIS가 실시간을 주면서 계좌를 요구하는 이유가 이것이므로, "KIS 말고 무료 실시간"은 존재하지 않는다.

### 실측 (2026-08-19 15:32 KST, 삼성전자)

| 소스 | 지연 | 키 | 응답 | 연속호출 | 히스토리 |
|---|---|---|---|---|---|
| 네이버 금융 | **0.8분** | 불필요 | 51ms | 10/10 | 1999-01-04~ 6,812일봉 (외국인소진율 포함) |
| Yahoo Finance | **20.0분** | 불필요 | 1,404ms | IP 단위 429 위험 | 분봉 지원 |
| 공공데이터포털 금융위 | T+1 13시 | 자동승인 | — | 1만/일 | 기간조회 지원 |

두 무키 소스가 같은 가격을 반환해 교차검증됨(247,500 vs 247,000).

### 리서치 충돌과 해소

공식소스 조사는 네이버를 **비권장**(비공식·약관), 해외커버리지 조사는 네이버를 **1위 추천**(무료·실시간·안정)했다. 둘 다 옳다 — 답은 소스를 고르는 것이 아니라 **용도로 계층을 나누는 것**이다.

```
OFFICIAL     공공데이터포털 금융위 · KRX Open API     T+1 일별, 약관 명확
             → 위키에 영구 저장되는 사실은 여기서만

BEST_EFFORT  Yahoo(20분) · 네이버(~실시간)            무키, 비공식/회색
             → 장중 "지금 얼마?" 휘발성 조회 전용

REALTIME     KIS · 키움 (계좌 필요)                    나중에 어댑터만 추가
```

**핵심 불변식: `official === false` 데이터는 위키에 커밋하지 않는다.** 검증에서 6,812건 비공식 데이터가 커밋 단계에서 실제로 차단되는 것을 확인했다. 이 구조 덕분에 비공식 엔드포인트가 깨져도 **축적된 지식 자산은 무사하고 현재가만 안 보인다.**

### 라이선스 — 네이버·다음·토스를 기본에서 뺀 이유

KRX 「시세정보 이용정책」(2024-01-01 시행) **§2 [옵션3] "웹사이트 체결가서비스용"**은 포털의 시세 **화면 표시는 허용**하되, *"정보를 이용하는 제3자가 전자적 방법으로 가공·저장·재분배할 수 있는 수단·도구·지원(API, DDE 등 포함)의 제공은 엄격히 금지"*한다.

**네이버가 공개 API를 두지 않는 것은 기술적 선택이 아니라 라이선스 의무**이고, 그 내부 엔드포인트를 프로그램으로 긁는 것은 이 금지를 우회하는 셈이다. 사람이 화면을 보는 것은 정상 이용이지만 자동 수집은 다르다.

→ 어댑터에서 네이버·다음·토스를 **`optIn: true`로 기본 비활성**했다. 기본 체인은 야후(20분)만 남고, 사용자가 `allowUnlicensed: true`를 명시해야 실시간 소스를 쓴다. 히스토리는 더 엄격해서, 공식 키가 없으면 **조용히 폴백하지 않고 키 발급 안내와 함께 에러를 낸다**(위키에 축적되는 정본이므로).

§8 「비조회형 정보이용」도 유의점이다 — 계량분석·포트폴리오관리는 단순 조회와 별개로 신고·별도 이용료 대상일 수 있다. 개인 자기자산 관리 목적이면 §7 「개인가입자」 범위 안이다.

### 정정 — "무료 실시간 불가능"은 공식 경로에 한정된 말이다

앞 문단의 "무료 실시간 불가능"은 **공식·합법 채널**(코스콤 계약, 증권사 API)에 한정된 사실이다. 공개 엔드포인트는 실제로 실시간을 준다. 15:49 KST 재측정:

| 소스 | 지연 | 세션 | 비고 |
|---|---|---|---|
| 네이버 m.stock | **0.0분** | 시간외 | `overMarketPriceInfo`로 장 마감 후 시간외까지 추종 |
| 네이버 polling | **0.0분** | 시간외(AFTER_MARKET) | 별도 경로 — 네이버 내 이중화 가능 |
| 다음 금융 | 정규장 실시간 | 정규장만 | 마감 후엔 15:30 고정. `Referer` 헤더 필요 |
| Yahoo | 20분 | — | 측정 중 **429 발생** (내 이전 호출로 IP 예산 소진) |
| Google Finance · stooq | — | — | 사용 불가 (파싱 실패 / 한국 미지원) |

**타임스탬프 함정**: 처음 측정에서 다음을 "408분 지연"으로 잘못 읽었다. `date` 필드는 날짜만 담고 체결 시각은 `tradeDate`+`tradeTime`에 따로 있다. 네이버도 `localTradedAt`은 정규장 마감(15:30) 고정이고 시간외 실시간은 `overMarketPriceInfo` 안에 있다. **소스마다 시각 필드 의미가 달라 그대로 믿으면 지연을 오판한다.**

**Yahoo 429는 실재하는 취약성이다.** 앞선 검증에서 페이싱을 지켰는데도 이후 버스트로 차단됐다가 몇 분 뒤 복구됐다. 1차 소스로 쓸 수 없다.

폴백 체인 확정: **네이버(0분) → 다음(정규장) → 야후(20분)**, 3소스 전부 동작 확인.

### 어댑터 구현에 반영한 실측 사항

- **야후 페이싱 1.1초 강제** — 무지연 15연속 시 IP 단위 429가 7분 이상 지속된다(짧은 백오프로는 못 뚫음). 1.1초 간격에서는 5연속 전부 성공.
- **야후 심볼 신선도 검증** — 접미사를 틀려도 200에 엉뚱한 과거 데이터를 준다. `regularMarketTime`으로 검증해 조용한 오답을 막는다.
- **네이버 응답은 엄격한 JSON이 아님** — 차트 헤더 행이 작은따옴표라 관대한 파싱 필요.
- **폴백 시 `degraded: true` + 사유 기록** — 왜 비공식 소스로 내려갔는지 남긴다.

### ⚠️ 내 첫 구현은 장중에 깨졌다 — 다른 조사가 잡아낸 결함

`m.stock.naver.com/api/stock/{code}/basic`의 `overMarketPriceInfo`를 우선하는 로직으로 "0.0분"을 측정했는데, **그 값은 장 마감 후에만 성립한다**:

- `overMarketPriceInfo`는 시간외에만 존재하고 **정규장(09:00~15:30)에는 `null`**이다
- null이면 최상위 `localTradedAt`으로 폴백하는데, 이 필드가 **38~252초 지연**되고 **최대 61초 역행**한다(독립 재현)
- 즉 정작 장중에는 지연 + 가격 역주행이 발생하고, `lagMinutes`가 음수로 나올 수도 있었다

**수정**: `polling.finance.naver.com/api/realtime/domestic/stock/{codes}`로 교체. 같은 네이버라 라이선스 판단은 그대로지만 정규장·시간외 모두 `delayTime: 0`이고, **1회 요청에 최대 1,000종목**을 준다(8종목 24ms 실측). 응답에 서버가 권장 폴링 주기(`pollingInterval: 7000`)를 실어 보내므로 그 값을 존중한다.

> 장 마감 후에 측정한 "실시간"은 실시간이 아닐 수 있다. 세션이 바뀌면 데이터 경로가 바뀐다.

### 토스증권 — 성능은 최고, 리스크 등급은 한 단계 높다

`wts-info-api.tossinvest.com/api/v2/stock-prices/A{code}` — 키·헤더·계좌 전부 불필요, KRX+NXT 통합가, 지연 0.2~1초. **네이버와 완전히 독립된 사업자**라 상관 장애 위험이 없다.

⚠️ **다만 다른 비공식 소스와 리스크 성격이 다르다.** 네이버·다음은 내가 계정을 갖고 있지 않지만 토스증권은 **실제 증권계좌 사업자**다. WTS 내부 API를 긁는 최대 오픈소스 래퍼조차 스스로 *"토스증권 이용약관 위반에 해당할 수 있으며 계좌 제한·손실에 책임지지 않는다"*고 경고한다. 토스 계좌 보유자에게는 실자산이 걸린 문제다.

→ 어댑터에서 `riskLevel: 'elevated'`로 분류해 **`allowUnlicensed`만으로는 켜지지 않게** 했다. `allowElevatedRisk`를 추가로 켜거나 `prefer: ['toss']`로 명시해야 쓰인다.

> 토스는 **2026-08-13 공식 Open API를 정식 출시**했다(REST 전용, 계좌 필요, 초당 15회). 토스 계좌가 있다면 내부 API를 긁을 이유가 없다 — 공식 경로를 쓰면 된다.

실측 교차검증: 네이버 254,000원 / 토스 254,000원(둘 다 시간외 0.00분), 다음 247,500원 / 야후 247,500원(둘 다 정규장 종가). **같은 세션끼리는 정확히 일치하고 세션이 다르면 갈린다** — 오늘 시간외에서 +2.4% 벌어졌다. 세션 표기 없이 섞으면 앱이 거짓말을 하게 된다.

### WebSocket은 계좌 없이 불가능 (확정)

네이버는 `wss://` 참조가 번들에 0건 — 순수 폴링이다. 토스는 `wss://realtime-socket.tossinvest.com/ws`가 익명 업그레이드를 수락하지만(HTTP 101) STOMP CONNECT에서 자격증명을 요구한다. **push가 필요하면 증권사 계좌가 실질 조건이다.**

### 소스 안정성 등급 (관측 기반)

| 소스 | 등급 | 근거 |
|---|---|---|
| 네이버 polling | 중상 | 서버가 폴링 주기를 직접 알려줌, 10년+ 하위호환 유지 |
| 토스 | 중 | 현대적이나 이력 불명 |
| 다음 | **하** | API 표면 붕괴 중 — `/quotes`만 생존, `/days`·`/charts`·`/orderbook` 전부 500 |
| 야후 | 하 | IP 단위 429 공격적 |

`api.stock.naver.com/stock/{code}/basic`은 **409 `Not Exist Master`** — 과거 동작하던 엔드포인트가 죽은 실례다. 넷 다 미문서화 내부 API이므로 **예고 없는 변경을 정상으로 전제하고 설계한다.**

### 나중에 공식 실시간을 원한다면 — 증권사 경로

모의투자로 계좌를 우회할 수 있는지 조사한 결과: **불가능하다.**

- **기술적으로는 KIS 모의투자 앱키로 실시간 WebSocket이 나온다.** 공식 저장소에 모의 전용 엔드포인트(`ws://ops.koreainvestment.com:31000`)가 정의돼 있고, 국내주식 실시간 API 25종 중 모의 미지원 표기가 붙은 것은 하나도 없다(미지원은 국내선물옵션 2건뿐).
- **그러나 절차적으로 실계좌가 선행 필수다.** 모의투자 앱키는 실계좌 개설 → 로그인 → 모의투자 신청 → 발급된 모의 계좌번호로 재신청하는 순서라, 계좌를 건너뛰는 경로가 아니다. 게다가 KIS 모의투자는 **참가 기간 최대 3개월**이라 만료 시 재신청·키 갱신이 필요하다.
- **키움도 "당사 계좌 보유 + HTS ID 연결" 필수**이며, 더 나쁜 함정이 있다 — *"접속 기준은 실서버로, 모의투자 서버로만 로그인하면 서비스가 자동 해지될 수 있습니다"*. 모의투자만 쓰면 3개월 후 API 권한이 회수된다.
- LS·토스·KB·DB·NH 전부 자사 계좌 요구. **예외 없음.**

계좌를 열기로 한다면 **개설 마찰이 증권사마다 다르다.** macOS에서 쓸 수 있는 곳만 추리면:

| | 키움 REST | 토스 Open API | KIS |
|---|---|---|---|
| **20영업일 제한** | **미적용** ✅ | **미적용** ✅ | 적용 ⚠️ |
| 세션당 실시간 종목 | **200** | — | 40 |
| WebSocket | ✅ | **❌ REST 전용** | ✅ |
| 조회 한도 | 초당 5회 | 초당 15회 | 초당 20건 (모의는 2건) |
| 자동해지 | 3개월 **미접속** | 조항 없음 | 1년 미이용 |
| 라이브러리 생태계 | 신생(공식 REST ★31) | 신생 | **압도적**(공식 ★1,572) |

**1순위 키움** — 20영업일 제한이 없어 다른 계좌 이력과 무관하게 당일 개설되고, 실시간 200종목이면 개인 앱에 충분하다. 자동해지 기준이 "미접속"이라 **앱이 매일 한 번 호출만 하면 무기한 유지**된다. 마찰: IP 등록 필수(최대 10개), 앱키 다운로드 1회 한정.

**2순위 토스** (2026-08-13 정식 출시) — 개설이 가장 쉽고 유지 조항이 아예 없다. 단 **WebSocket이 없어 REST 폴링만** 가능하고 모의투자 환경도 없다. 스트리밍이 필요 없다면 1순위.

**3순위 KIS** — 문서·라이브러리는 최강이지만 20영업일 제한이 걸리고 웹소켓 동시구독이 40건뿐이다.

**피할 곳**: LS·NH는 *"3개월간 체결 20건 이하 시 해지"* 조항이 있어 **거래를 안 할 목적과 정면 충돌**한다. 대신(32bit COM)·하나(OCX)·신한(OCX)은 macOS 불가, 미래에셋은 2017년 신규 중단, 삼성·카카오페이는 개인용 API가 없다.

### 20영업일 제한 — 정확한 작동 방식

**"보유"가 아니라 "개설 이벤트"가 트리거다.** 금감원 공개Q&A 2023Q1883: *"최근 20영업일 이내에 서로 다른 금융회사에서 1개 이상의 계좌를 **개설한 경우**"*. 예전에 만들어둔 기존 계좌를 여러 개 갖고 있는 것 자체는 무관하다. 단 카운팅은 **전 금융권 통합**이라 은행 통장을 새로 튼 것도 증권계좌 개설을 막는다.

법령이 아니라 **금융회사 자율 규범**이라 적용 여부가 갈린다 — 키움·토스는 미적용, 한투·LS·NH·KB·미래에셋·삼성은 적용. 인터넷에 도는 "제한 없는 곳: 키움·삼성·한화·LS·유진" 목록은 오래된 정보다.

> 여러 곳을 열 계획이면 **제한 있는 곳(한투)을 먼저**, 같은 날 키움·토스를 추가한다. 반대 순서면 한 달 막힌다.

### 계좌를 열고 방치하면 사라진다

API 수수료가 0원이라 **잔고 0원 자체는 어디서도 API 차단 사유가 아니다.** 문제는 계좌 쪽이다 — 금융투자협회 「매매거래계좌설정약관」 제15조상 **잔액이 "영"이 된 날로부터 6개월이면 계좌 폐쇄가 가능**하고, 10만원 이하 + 6개월 무거래면 휴면 편입된다.

→ 개설 직후 **1만원 정도 입금**해 두고, 앱이 **매일 실서버 시세 API를 한 번 호출**하도록 설계하면 자동해지와 휴면을 동시에 피한다. 매매는 안 해도 된다.

### 배제한 경로

- **pykrx 계열 금지** — `data.krx.co.kr`이 2025-12-27 회원제 'KRX Data Marketplace'로 개편되며 로그인 필수화, 스크래핑 방식이 깨져 이슈 미해결. 약관상 자동수집 명시적 금지, 과거 IP 차단 및 "해제 원칙적 불가" 통보 전례.

## 7. 공시 → 이벤트 추출 → 위키 생성 파이프라인 ⭐

`spikes/pipeline/extract.mjs` · 13/14 통과

**제품의 심장.** DART 키가 없어 EDGAR로 검증했지만 파이프라인 형태는 동일하다: 공시 원문 → LLM이 스키마에 맞춰 추출 → 마크다운 위키 페이지 → SQLite 인덱스.

씨앗으로 기존 위키 7페이지를 깔아두고, 에이전트에게 NVDA 최근 8-K를 Event 페이지로 만들라고 시켰다. 8턴 / 75초.

| 검증 | 결과 |
|---|---|
| 기존 위키를 먼저 읽음 (Glob + Read 3회) | ✅ |
| 노드 타입이 스키마 내 (`Event`) | ✅ |
| 엣지 관계가 전부 스키마 내 | ✅ |
| 출처 URL·날짜 존재 | ✅ |
| **기존 엔티티 재사용 — 중복 생성 안 함** | ✅ `company-nvidia` 재사용 |
| 인덱서가 파싱 가능 (스키마 왕복) | ✅ |
| 새 페이지가 그래프에 연결됨 | ✅ |
| 외부 MCP 유입 0개 | ✅ |

**LLM이 정직하게 썼다.** 8-K 본문을 읽지 않았으므로 태그에 `본문미확인`을 달고 *"도구가 반환한 메타데이터는 다음이 전부다"*라고 명시했다. 제출인 확정 사실에는 `confidence: 0.99`, 관계는 `affects`가 아니라 `about`을 골랐다 — 공시는 회사에 영향을 주는 게 아니라 회사에 *관한* 것이므로 정확한 판단이다.

### 실패한 1건 — 빌트인 도구 노출은 `disallowedTools`로 다 못 막는다

`allowedTools`에 `Read/Write/Glob/Grep`만, `disallowedTools`에 `Bash/Task/WebFetch/WebSearch/NotebookEdit`를 넣었는데도 **빌트인 23개가 노출**됐다: `CronCreate` `DesignSync` `EnterWorktree` `Monitor` `PushNotification` `RemoteTrigger` `ScheduleWakeup` `SendMessage` `Skill` `TaskOutput` `TaskStop` `ToolSearch` `Workflow` 등. 에이전트는 실제로 `ToolSearch`를 호출했다.

지정한 차단은 정확히 먹었으므로 **`disallowedTools`는 동작하되 목록을 다 적어야 한다.** 앱에서는 화이트리스트 방식으로 뒤집어, 필요한 것 외 전부 차단하는 헬퍼를 두는 것이 안전하다.

> 검증 코드 자체의 교훈: 처음엔 이 검사를 `chk('외부 MCP 유입 없음', true)`로 **하드코딩**해놓고 12/12 통과라고 읽었다. 실제 노출 목록으로 검사하도록 고치자 14개 중 1개가 실패로 드러났다. 통과하는 검증은 통과하도록 짜여 있을 뿐일 수 있다.

## 8. 설계 변경 사항

**빌트인 파일 도구를 위키 편집에 재사용한다.** SDK가 `Read`/`Write`/`Edit`/`Glob`/`Grep`을 이미 제공하므로, 위키 마크다운 CRUD 도구를 따로 만들 필요가 없다. 작업 디렉터리를 위키 폴더로 고정하고 빌트인을 쓰되, 커스텀 도구는 SQLite 인덱스가 필요한 작업에만 만든다:

- `wiki_graph_query` — 관계 탐색 (k-hop 이웃, 엣지 타입 필터)
- `wiki_search` — trigram/LIKE 라우터가 붙은 전문검색
- `find_similar_cases` — 과거 Decision 소환
- `decision_record` / `decision_update` — 의사결정 저널 쓰기 (스키마 검증 필요)

빌트인 중 `Bash`, `Task`, 워크트리·크론 계열은 `disallowedTools`로 차단한다.

**네이티브 의존성을 쓰지 않는다.** Node 24 내장 `node:sqlite`가 FTS5 trigram을 지원한다(SQLite 3.53.3). `better-sqlite3` 같은 네이티브 모듈이 필요 없으므로 Electron 리빌드·서명·크로스플랫폼 배포가 크게 단순해진다.

DART 키가 나오면 **"공시 → 이벤트·관계 추출 → 위키 페이지 생성"** 파이프라인을 바로 검증한다. 이것이 남은 유일한 미검증 핵심 경로다.

### 실시간에 대한 판단

기능별로 따져보면 실시간이 없어서 **못 하는 기능은 없다**:

| 기능 | 필요 정밀도 |
|---|---|
| 데일리 브리핑 · 위키 축적 · 유사케이스 소환 · 결과 추적 | 일별로 충분 |
| Decision 기록 시점 스냅샷 | 분 단위면 충분 |
| invalidation_condition 점검 | 시세가 아니라 **공시·재무**가 핵심 |
| 장중 "지금 얼마?" | 20분 지연도 대체로 수용 가능 |

정작 실시간성이 중요한 것은 **DART 공시이고 그건 무료로 즉시 열린다.** "시세는 T+1, 공시는 실시간"이 이 앱의 실제 구조다.
