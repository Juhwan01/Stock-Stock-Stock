| 앱 기획의 요소 | 레포 에이전트에서 |
|---|---|
| 앱 실행 | 이 레포에서 `codex` 실행 — `AGENTS.md` 규칙과 MCP 도구가 자동으로 붙는다 |
| 앱 열 때 브리핑 생성 | launchd가 평일 아침 `scripts/briefing.sh` → `codex exec` → `briefings/YYYY-MM-DD.md` |

## S0. 첫 실행 — 설치한 날 저녁

레포를 clone하고 `npm install`한 뒤 `codex`를 처음 켠다. 위키는 텅 비어 있다.

| 단계 | 흐름 | 상태 |
|---|---|---|
| 1 | 점검 스크립트: Codex 로그인(`codex login status`) · 과금 경로(`CODEX_API_KEY` 미설정) · Node 버전 · 데이터 키 → 빠진 것만 안내 | 🔧 (8-20 공백이던 전제조건 명시는 PLAN.md에 반영: Codex CLI 설치 + ChatGPT 로그인) |
| 2 | 키 온보딩: `codex`에게 "설정 시작" → DART·공공데이터포털 발급 링크 안내 (각 5분) → **키는 대화가 아니라 `.env`에 직접 입력** → 검증 도구가 실제 호출로 확인 | 🔧 — 키를 대화에 붙여넣으면 세션 로그에 남는다 *(전환으로 발견)* |
| 3 | 관심종목 등록: "삼성전자, SK하이닉스, NVDA 추가해줘" | ✅ M2 — `watchlist_update` (대화형 승인), `wiki/portfolio.yaml` |
| 4 | **콜드 스타트 백필**: 관심종목 최근 1년 공시 + 10년 시세를 인제스트해 시드 위키 생성 | ⚠️ **가장 큰 공백.** 이게 없으면 첫 몇 주간 "소환할 과거"가 없어 핵심 가치를 체감하기 전에 이탈한다 |
| 5 | 백필 실행: `codex exec`로 백그라운드 실행, 종목 단위로 위키 페이지가 생기며 진행 로그 기록 | 🤔 백필은 구독 한도를 한 번에 크게 쓴다 — 종목을 나눠 며칠에 걸쳐 돌릴지 결정 필요 *(전환으로 발견)* |

## S1. 평일 아침 — 08:40 브리핑

08:00에 launchd가 브리핑을 미리 만들어 둔다. 출근 전에 `briefings/` 폴더의 오늘 파일을 열거나, `codex`에서 "오늘 브리핑"이라고 묻는다.

| 단계 | 흐름 | 상태 |
|---|---|---|
| 1 | 마지막 실행 이후 델타 수집: DART 공시·뉴스 헤드라인·전일 시세 | 🔧 |
| 2 | **에이전트 triage**: 밤새 공시 30건 → "위키 반영 제안 2건 / 참고 7건 / 무시 21건" | ✅ M2 — 실데이터 17건 → 1 / 1 / 15 (Codex 실측 약 70초) |
| 3 | 제안 검토: `codex`에서 "제안 검토하자" → "이 공시를 Event로 추가할까요? 연결: [[company-hynix]] affects(+)" → 승인/수정/거절 → 승인분만 위키 커밋 | ✅ M2 — `proposal_list` → 승인 시 페이지 작성 + `proposal_resolve` |
| 4 | 열린 Decision 점검 결과: "무효화 조건 관련 신규 데이터 없음" | 🔧 |
| 5 | 생성 시간: Codex 실측 공시 조회 18초 / 위키 루프 35초 → 예약 실행이라 기다릴 일이 없다. 확인하기 전에 끝나 있으면 된다 | ✅ 설계로 해소 |
| 6 | **구독 사용량**: 매일 브리핑이 ChatGPT 구독 한도(5시간 창 + 주간)를 소모 → 브리핑은 경량 모델(현재 GPT-5.6 Luna), 대화는 상위 모델 | 🔧 PLAN.md Phase 1 반영 (`codex exec -m`) |
| 7 | 맥이 잠자기 중이었다면 launchd는 깨어날 때 작업을 실행한다 → 처음 확인할 때 아직 생성 중일 수 있음 | 🤔 *(전환으로 발견)* |

| 5 | 결과 기록을 미루면 → 다음 브리핑마다 리마인드 | ⚠️ 소소하지만 미정 |

## 결론

핵심 루프(수집→축적→판단→되먹임)와 위험 구간(인증·데이터·스키마·검색)은 검증됐고, **공백은 전부 "루프 자체"가 아니라 "루프를 매일 쓰게 만드는 운영 UX"에 있다** — 콜드 스타트, 확인 피로, 조건의 판정 가능성, 한도 관리. 넷 다 Phase 1~2 설계에 흡수 가능한 크기이며 아키텍처 변경을 요구하지 않는다.

레포 에이전트 전환은 루프를 건드리지 않는다. 바뀐 것은 트리거(앱 열기 → 예약 실행)와 승인 경로(카드 → 대화)뿐이고, 새 공백 중 무거운 것은 **대기 중 제안의 저장 형식** 하나다. 인증 경로(Codex + ChatGPT 구독)와 도구 격리는 Codex에서 다시 검증해야 한다 (PLAN.md Phase 0).
